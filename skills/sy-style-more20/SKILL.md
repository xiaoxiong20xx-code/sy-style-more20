# 再来 20 种（sy-style-more20）

20 条 10 秒的纯画面短片（1920×1080、30fps、带程序合成的配乐音效，画面里没有文字和署名）。每一帧都是代码在无头浏览器里算出来的，`make.js` 一条命令出片。用户多半是**完全不懂编程的小白**，你替他把事情做完，再用一两句大白话告诉他结果。

这是第三批（编号 41–60）。上一批 21–40 是另一个包 sy-style-new20，用法一样，但**不在这个文件夹里**：用户要 21–40 的风格，告诉他去 https://github.com/xiaoxiong20xx-code/sy-style-new20 下载那个包。

## 1. 先找到包

包的位置：`{{PACKAGE_DIR}}`

- 安装程序会把上面这行换成真实路径。如果上面还是两对大括号包着的占位符（没换成路径），说明这份说明书是在包里直接读的：包的位置 = 这个 SKILL.md 往上两层、有 `make.js` 的那个文件夹。
- 下面所有命令都要**在包的文件夹里**运行：先 `cd` 进去，再 `node make.js ...`。
- 文件夹不存在（用户挪过或删了）：请用户告诉你包现在在哪；或者请他在新位置重新双击安装文件（`安装-Windows.bat` / `安装-Mac.command`），路径会自动更新。

## 2. 每次开工先检查

```
node make.js check
```

- 全是 √ 就直接干活。
- 有 × ：告诉用户缺什么，请他**双击包里的「安装-Windows.bat」**（Mac 是「安装-Mac.command」）重新装一遍，装完关掉终端 / 重开 AI 助手再继续。不要自己去改系统设置或全局配置。
- “显卡”一项是 · 不是 √：出图（still）没问题，但正式片要用软件渲染，一条要几个小时到几天（见第 5 节）。这时 `style` 不会自己开始，会列出 3 个办法：下载 Releases 里的成片 / `--draft` 草稿 / `--cpu` 过夜跑。**这是少数要先问用户的情况**：用大白话把这 3 个办法和要等多久告诉他，让他选。

## 4. 出片

```
node make.js style 57          # 一条（也可以写 万花筒、kaleido）→ out/57-万花筒.mp4
node make.js style 52 54 55    # 几条
node make.js style all         # 全部 20 条
node make.js still 57 5        # 只出一张图（第 5 秒）→ out/57-万花筒_5s.jpg，几秒到一分钟
node make.js still 59 5 8 --compare  # 改过之后：原版和现在左右对比 → out/59-冰雕_5s_对比.jpg 等（59 用 5 8：底座灯 4 秒才亮）
node make.js sheet 57          # 从成片抽 9 帧拼联系表 → out/57-万花筒_联系表.jpg
node make.js status            # 看进行到哪了（也可以直接读 out/进度.txt）
node make.js list              # 列出 20 种
```

要点：

- **出片有显卡一条也要 3 分钟到一个多小时（52 机械表芯约 72 分钟、53 烙画约 50 分钟），一定放后台跑**，不要用默认的 2 分钟超时去等。Claude Code：Bash / PowerShell 工具加 `run_in_background: true`，跑完会通知你；其他 AI 助手用它们的后台 / 长任务方式，或者请用户自己在终端里运行这条命令。跑的过程中可以用 `node make.js status` 看进度。
- 开工前先说一句大概要多久（按第 3、5 节的耗时档）。
- 会自动：用显卡（Windows 上会自己选好显卡接口，出问题会换一种再试；草稿和单张图可以退回软件渲染）、显示进度和剩余时间、配乐音效、把响度调到 -15 LUFS（真峰值 ≤ -1 dBTP）、做完删掉临时帧。
- **中断了**（关了窗口、电脑睡眠、报错）：再运行同一条命令，会从停下的地方接着做。
- 已经做好、画面又没改过的，会直接跳过（提示“已经做好了”）。要强制重做加 `--force`。
- **出完片先自己看一眼**：`node make.js sheet 编号` 出联系表（`out/编号-中文名_联系表.jpg`，9 帧），用读图工具看有没有黑屏、花屏、穿帮、颜色不对，没问题再告诉用户。
- 片子在包里的 `out` 文件夹，文件名 `编号-中文名.mp4`。做完告诉用户**完整路径**；用户想看就帮他打开文件夹（Windows：`explorer out`；Mac：`open out`）。
- 想快速看一下动起来的样子：`node make.js style 57 --draft`（半分辨率、不加运动模糊，快好几倍）→ `out/57-万花筒_草稿.mp4`。

## 6. 常见报错怎么办

| 看到的提示 | 怎么办 |
|---|---|
| 还不能出片：渲染组件 / ffmpeg / Python 没装 | 请用户重新双击安装文件，装完重开终端或 AI 助手。刚装完找不到 ffmpeg / Python，多半也是没重开。 |
| 显卡渲染没成功，换一种显卡接口再试 | 不用管，它会自己在 gl 和 d3d11 两种接口之间换着重试。都不行时会停下并列出办法（下载成片 / 草稿 / `--cpu`），转告用户让他选。 |
| 没检测到能用的显卡……（退出码 3） | 不是出错，是提醒：没显卡时正式片一条要几个小时到几天。把提示里的 3 个办法告诉用户，按他的选择运行。 |
| 画面全黑、花屏、颜色怪 | 多半是显卡驱动的问题。先 `node make.js still 编号 5 --cpu` 出一张软件渲染的图对比；再换显卡接口试：Windows 上 `set SY_ANGLE=d3d11`（PowerShell：`$env:SY_ANGLE='d3d11'`）或 `gl` 后加 `--force` 重出。**不要用 vulkan**（会偶尔截出全黑的帧）。都不行才用 `--cpu --force`（很慢，见第 5 节）。 |
| 54 X光透视 渲染崩溃 / 加载失败 | 54 在 OpenGL（gl）接口下会崩，它的 `render.args` 里写了 `--angle d3d11`，make.js 会自动用 d3d11。别手动给它设 `SY_ANGLE=gl`。没有显卡的电脑出不了 54（软件渲染一张图一个多小时都算不完），make.js 会跳过它并提示下载成片。 |
| 硬盘剩余空间不够 | `node make.js clean` 删临时帧；成片在 out 里不受影响。每条渲染时临时要几百 MB 到 1 GB 多（52 机械表芯最多），做完自动删；出片前要求至少剩 2 GB。 |
| 没找到「xxx」这种风格 | 看 `node make.js list`，用编号最稳。用户说的是 21–40 的风格（比如字符画、彩色玻璃窗）：那是上一批 sy-style-new20，不在这个包里。 |
| 合成声音失败 | 多半是 numpy / scipy 没装好：重新双击安装文件。 |
| 响度不在范围内 | 很少见。make.js 已经会自动补一次（更低的限幅、只换声音）。还不行就 `--force` 重出一次，并把提示原文发给作者。 |
| 加载失败 / 超时 | 软件渲染时第一次准备可能要几分钟，正常；显卡模式超时会自动换别的显卡接口重试。反复失败就把报错原文发给作者。 |

## 7. 用户要改颜色、光线、速度、内容

每个风格是 `styles/编号-名字/index.html`（一个网页，里面是画面代码：JS + 着色器字符串 GLSL）+ `music.py`（配乐和专属音效）+ `render.args`（渲染参数）。55 声音的形状还多一个 `table.js`（每一拍的音高和沙纹，画面和声音都读它）。

### 改的流程（每次都这样）

1. **先备份**：把 `index.html` 复制一份叫 `index.原版.html`（已经有了就别覆盖，它是最初的原版）。
2. 查下面 7.2 的对照表，找到要改的地方，再读那一段代码确认。
3. 改代码。
4. 出对比图自查：`node make.js still 编号 1 5 9.5 --compare`（59 冰雕用 `5 8`：底座灯 4 秒才亮；其他条用 `1 5 9.5`） → `out/编号-名字_5s_对比.jpg` 等（左原版、右修改后）。**自己用读图工具看一遍**：改对了没有、有没有黑屏、穿帮、颜色爆掉、光柱 / 光斑这些显眼的地方有没有一起变。注意有的光是某一秒才亮的（比如 59 冰雕的底座灯 4 秒才亮、44 糖画的背光 4 秒才亮、55 声音的形状 8 秒切灯），对比的时间点要选在那束光亮着的时候。
5. 把对比图给用户看，一句话说清改了什么。用户满意再 `node make.js style 编号` 出正式片（改过的会自动重做），做完照第 4 节看一眼联系表。
6. 用户说“换回原版”：把 `index.原版.html` 拷回 `index.html`。

### 7.1 改光色和改配色是两回事

- **改光色**（“偏蓝的晨光”“暖一点”“像傍晚”）：要找**光进入着色的地方**——灯的颜色乘到受光面上的那一步（常见写法：`alb * (光色 * 漫反射 + 环境光)`、`光色 * 高光`、光柱里 `acc += L * dust`），在那里乘光色。一束光往往不止一个入口：受光面、高光反射、光柱 / 雾、地上的光斑、溢光、反弹光，**要全部乘到**，不然最显眼的光柱、光斑不变。
- **改配色**（“糖换成绿色”“布更蓝”）：改物体本身的颜色（调色板、材质色）。改了配色，光的冷暖不会变。
- **已经做好“光色旋钮”的 17 个场景**（表里打 ★ 的：41–53、55、57、59、60）：只改文件里的 `LIGHT_COL`，默认 `vec3(1.)` = 和成片一模一样（已经逐像素核对过），乘上去的值就是光色的偏移。**先看灯本身的底色**（表里写了），推荐值要够狠才看得出来：
  - 灯本身偏暖的（41、42、43、44、45、46、47、50、51、53、55、57、60：台灯、暖窗光、油灯、炉火）：要变冷，蓝拉到 1.5 以上、红压到 .7 以下，例如 `vec3(.62, .85, 1.65)`（53 实测明显变成冷白月光）。`vec3(.78, .88, 1.15)` 这种轻的只会变成中性白。
  - 灯本身接近白光或偏冷的（48、49 的日光，52 的影棚白光，59 的冷蓝 LED）：要变暖，红拉高、蓝压低，例如 `vec3(1.3, 1., .6)`（49 实测明显偏暖黄）；59 冰雕的 LED 是冷蓝，红要拉到 2 以上，见表。
  - 更暗：整体乘一个小于 1 的数（别低于表里说的辉光阈值）。
  - 不管哪种，改完都出对比图看一眼，不够明显就再加大差距。
- 几个特别的：
  - 44 糖画有两个旋钮：`LIGHT_COL` 是摊位顶灯，`BACK_COL` 是 4 秒亮起的背后灯泡。
  - 59 冰雕的 `LIGHT_COL` 写在 JS 里：`const LIGHT_COL = [1, 1, 1];`（数组，会自动填进着色器，同时管飘雪），不要在着色器里再写一份。数字写普通小数，别写 `1e-1` 这种。

### 7.3 场景的规矩（一定要守）

- `render(t)` 必须是**确定性**的：同一个 t 永远画出同一张图。不能用 `Math.random()`、`Date.now()` 驱动画面，随机用 `Reel.rng(种子)` 或哈希。
- 时长 10 秒、30fps、1920×1080 不要改。节拍是 120 BPM（每拍 0.5 秒），动作落在拍点上；4–5 秒是钩子，8.0 秒落最后一拍，8.5–10 秒画面干净停住。
- 改速度：运动由 `cam(t)` 和各种 `(t)` 函数控制。音效时间点写在 `Reel.scene({ cues: [{ t: 4.0, sfx: '名字', gain: 0.9 }] })`。**改了动作的快慢，就要同步改对应 cues 的 t**，不然声画对不上。出片时会自动从网页里重新导出 cues，不用手动跑别的。
- 55 声音的形状：每一拍的音高和沙纹都在 `table.js`，画面（index.html）和配乐（music.py）都读它。改节奏、音高只改 `table.js`，两边自动对上。
- 音效 / 配乐：`music.py` 里的 `mus(...)` 每小节（2 秒）调用一次；`SFX_NEW = {名字: 函数}` 是这个风格专属的音效。乐器函数在 `audio/synth.py`。
- `render.args` 是渲染参数（一行，空格隔开）：
  - `--mb N`：运动模糊子帧数（每帧拍 N 张平均）。运镜改快了出现重影，就把 N 调大（越大越慢）。
  - `--soft`：柔和快门，子帧按升余弦加权平均（两头轻、中间重），快速移动的细线拖出一道连续的拖影，而不是几道分开的重影。子帧加到上百还有“台阶”，多半要加它。
  - `--shutter 0.9`：快门开多久（一帧时间的比例，默认 0.5）。
  - `--mbseg 3.25-7.0:112`：这一段（秒，含头不含尾，可以写多个）改用 112 个子帧。只给动作最快的几秒多取样，别的地方不浪费时间。
  - `--angle d3d11`：（只对 Windows 有效）这一条用哪种显卡接口。只有 54 需要。
  - 51 马赛克、52 机械表芯、53 烙画用了 `--soft --shutter 0.9 --mbseg …`，**别删**，删了快速段会出现台阶和分开的重影（成片就是这样渲的）。
- 文字：这 20 条没有画面文字。要加中文，用 `"Noto Sans CJK SC"`（字重只有 400 / 500 / 700），英文可用 `Inter`（500 / 600 / 700）、`DejaVu Sans Mono`、`TeX Gyre Heros Cn`。别的字体要先放进 `fonts/` 并在 `fonts/fonts.json` 登记（见 `fonts/LICENSES.md`）。

### 7.4 改快慢（用户说“转快一点”“慢一点”“动作快点”）

先说清楚三条底线，改速度时都不能破：

- **8.0 秒落最后一拍、8.5 秒以后画面静止**：所有动作在 8.0 收住，8.5–10 秒不能再动。
- **和音效、音乐卡在一起的时间点不能挪**：场景里 `cues: [...]` 写的每个 `t`、节拍表（55 的 `table.js`）都是声画对齐的。动作要快要慢，只改“两个卡点之间”的速度，卡点本身不动。
- **4–5 秒的钩子别挪走**。

大多数镜头运动是 `Track([...])` 或 `CK = [...]` 这样的关键帧表，每行一个 `t:`。想让某一段运镜慢一点，就在不碰 4.0、8.0 这类卡点的前提下，把这一段两头的 `t` 拉开一点（中间的点按比例挪），最后一行带 `stop: true` 的 8.0 别动。

常被问到的几条：

| 风格 | 能改的 | 绑死、别动的 |
|---|---|---|
| 41 青花瓷 · 转台 | 转速是 `function omega(t)` 里分 3 段的数。能改的只有展示时慢转 `return 0.42;`（4.2–7.2 秒，同一个数在上下两行各出现一次：`lerp(12.566, 0.42` 和 `lerp(0.42, 0`，要一起改，比如 0.7 = 快一倍多）；7.2–8.0 减速停在 8.0 | 作画时慢转 `return 0.12;`（0–2.8 秒）别改：毛笔是追着瓶面上每一笔的位置走的，瓶子转快了，笔画会转到侧面甚至背面，笔跟着跑偏。2.8–3.5 秒的快转 `12.566`（每秒两圈）用来甩出口沿那条青花带：它和 `const BAND = { y: 0.1555, t0: 3.0, t1: 3.5 }`、3.0 秒的 `wheel_spin` 音效绑在一起，时间和转速都别动。注意镜头 `CAM` 自己也在绕着瓶子走，只改转台的话，画面上感觉到的变化会比数字小，跟用户说一声 |
| 52 机械表芯 · 摆轮 | 摆幅 `AMP = 2.9`（弧度，约左右各 165°；改小摆得更“稳”，别超过 3.0，否则子帧之间会跳）。镜头穿过齿轮的速度在 `{ t: …, p: …, a: …, fov: … }` 那张关键帧表 | 摆轮频率是 `TICK = 0.25`：每个八分音符过一次中心、擒纵轮走一步，`k * TICK` 生成了 32 个嘀嗒音效，和 120 BPM 的配乐是对齐的，**不要改 `TICK`**，也不要改 `balanceAngle()` 里的 `2 * Math.PI * 2`（2 Hz）。8.0 的 `STOP` 是止秒杆卡住摆轮，别动 |
| 54 X光透视 · 转盘和小人 | 八音盒的转动是 `function yaw(t)`：0–8 秒从 `-0.5` 转到 `0.5`（弧度），把两个数改成 `-0.8, 0.8` 就转得快、角度大，但 8.0 停住时的侧影会变，出对比图看 8 秒那张；芭蕾小人在 `const spinB` 里 4.2–8.0 转 `2.5` 圈（改成 1.5 或 3.5，保持“几圈半”，8.0 才会正面朝镜头）；滚筒 `(Math.min(t, 8.0) - 4.0) * 0.9`、调速器 `* 60` 是转速 | 3.85 秒盒盖弹开（`lidAt`）、3.98 秒小人立起（`riseAt`）和 `lid_open` 音效对齐；4.0 起每个音符一拍（`const BEATS = [4.0, 4.5, …]` 和 `NOTES`）对应梳齿拨钉的声音，别动。`const slice = 0.5 / 30 / 24` 是按 `--mb 24` 算的，改了 `render.args` 的子帧数要同步改这里 |
| 57 万花筒 | 镜头退出目镜、再钻回去的快慢在镜头关键帧表 | 碎玻璃每拍翻一次（0.5–3.5 秒每拍一个 `tumble` 音效），4.0 的 `reveal_pull`、7.6 的 `dive_in`、8.0 的 `tumble_last` 都和画面卡死，翻动节奏别改 |
| 60 3D打印 · 打印速度 | 一般不建议改。长高的时间段是 `printAt()` 里的 `(t - 1.5) / 6.1`（1.5–7.6 秒长满）；0–1.5 秒是真实速度的第一圈 | 镜头 `CK` 在 4.1–6.4 秒是贴着正在打印的那一层往上走的，打印快慢一改，镜头就对不上层线；每拍一个 `timelapse_tick` 音效（1.5–7.5 秒）；7.95–8.45 秒喷头抬起、滑出画面 |
| 55 声音的形状 | 改节奏、音高只改 `table.js`（画面和配乐都读它，自动对上） | `table.js` 里的 `t` 要落在 0.5 秒的拍点上；8.0 的 `chord` 和 `cut = ofr >= 240`（第 240 帧切灯）别动 |

改完照第 7 节的流程出对比图，速度类的改动最好再出个草稿看动起来的样子：`node make.js style 编号 --draft`（快很多），满意再出正式片。

## 8. 和用户怎么说话

- 用户多半是小白：**简短、说人话、不甩术语、不贴日志**。
- 少提问：能自己判断就直接做，把假设说一句。比如“做出来”就是出正式片；“全部”就是 20 条；风格名对不上时列出最像的两三个让他挑。
- 开工时说：做哪几条、大概要多久、做完放哪。
- 完成时说：片子的完整路径、多长、用了多久；有失败的说清楚哪条、怎么办（通常是“再运行一次会接着做”）。
- 例：“万花筒做好了：D:\sy-style-more20\out\57-万花筒.mp4，10 秒高清带配乐，用了 4 分钟。要不要我顺手把 20 条都做了？”
